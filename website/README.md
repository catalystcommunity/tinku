# Tinku marketing site

A one-page explainer for Tinku, generated by
[PySocha](https://github.com/catalystcommunity/pysocha).

Edit `./site-src/`. PySocha writes the deployable static site to `./site/`.
Do not edit anything in `./site/` by hand: the next build replaces it.

`./site/` is committed, so a reviewer sees what changed in the output. The
container image builds the site again from `./site-src/`; it does not use
the committed copy. CI rebuilds on a pull request and fails if the
committed output does not match the source.

## Build

The build uses `uv` and a pinned PySocha commit:

```sh
./tools.sh build          # or, from the repository root: ./tools.sh site build
```

## Local preview

Build first, then serve the output:

```sh
python3 -m http.server 4173 --directory site
```

Open `http://127.0.0.1:4173/`.

`./tools.sh preview` runs PySocha's own preview server instead.

## Layout

| Path | Contents |
| --- | --- |
| `site-src/config.yaml` | PySocha settings. |
| `site-src/content/pages/index.md` | The page's text. Front matter holds the title and the hero copy. |
| `site-src/templates/page.jinja2` | The page itself. |
| `site-src/templates/blog.jinja2` | A stub. PySocha writes blog outputs even with no posts. |
| `site-src/content/extra_files/` | Files copied to the site root: the stylesheet, the script, and `assets/`. |
| `site/` | Generated. |

## Editing the text

Most copy is in the template, because it is structural: a heading and the
paragraph under it belong together. The front matter in `index.md` holds the
title, the meta description, and the hero.

## Colour and theme

The stylesheet defines one set of custom properties for the light theme on
`:root`, and overrides only those properties for the dark theme inside
`prefers-color-scheme: dark`. Every other rule names a property. To change a
colour, change the property.

The accent differs between the two themes on purpose. `#C04058` has enough
weight to read on a near-white page. On a near-black page it goes muddy, so
the dark theme uses `#E0445F`. Both give at least 4.5:1 against their own
background. The text colour on top of the accent flips with it: white on the
light theme, near-black on the dark one, because white on `#E0445F` is below
4.5:1.

## Hosting

Serve `site/` as static files. Every path in the page is relative, so the
folder moves without any URL changing.

```sh
rsync -av --delete ./site/ user@host:/path/to/tinku-site/
```

## Deployment

The site deploys to Kubernetes as a container image: Caddy serves the files
that `Dockerfile` builds. `values.yaml` configures the
`catalyst-helm/pysocha-site` chart, and the release has its own namespace,
`tinku-website`.

CI does the work, and it is the REPOSITORY's release that does it: a merge
makes a tag, and the tag deploys the site at that version along with
everything else the release publishes. See "Releases" in the root
`README.md`.

The site has no version of its own. It used to, which meant the repository
carried two version numbers that had to be remembered separately and could
disagree.

The deploy job refuses to run while `values.yaml` holds a placeholder
domain, because a real ingress for a name nobody owns is worse than no
deployment.

The job needs three values from the reactorcide secret store:

| Environment | Secret |
| --- | --- |
| `REGISTRY_USER` | `catalystcommunity/registry:user` |
| `REGISTRY_PASSWORD` | `catalystcommunity/registry:password` |
| `KUBECONFIG_CONTENT` | `catalystcommunity/k8s:kubeconfig` |
